Three fixes to the multi-select. Push all of these together — one of the bugs
was caused by pushing a subset last time.

1. "clearSelection" SHOWING AS A RAW KEY
   The string exists in i18n.jsx and always did. What reached the site was an
   older i18n.jsx without it — so the component asked for a key the deployed
   dictionary had never heard of.

   This is the second time a partial push has produced a bug that looks like a
   code fault. i18n.jsx is in this zip; it must go with the rest.

2. THE PANEL RAN OFF THE SCREEN
   It was anchored to the trigger's inline-START and grew outward from there.
   For the category filter, which sits toward the screen edge, that put the
   checkboxes past the edge with no way to reach them — your second screenshot.

   Now anchored to the inline-END, so it grows INTO the page. In RTL that is
   the right edge of the control, which is the predictable one here because
   the filter bar always starts near the same place.

   Long labels also wrap now instead of forcing the panel wider than the
   screen; "צריך להמשך השנה" was being cut mid-word.

3. HALF-WIDTH ON A PHONE MADE THEM USELESS
   I had paired them two-per-row like the plain selects. But a multi-select
   shows a label AND a summary — "סטטוס  ממתין לאישור, +2" — which needs about
   200px, and half a 393px phone row is 177px. It truncated to "סטטוס ▾", which
   says nothing about what is filtered.

   Full width on phones. A plain <select> survives half width because its text
   is short; this one does not.
