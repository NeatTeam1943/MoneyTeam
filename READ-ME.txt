WHAT IT SHOWED
    transactions_guest   200   the view works
    account_balances     200
    budgets              401   the MEMBER table, not the view
    transaction_lines    401   same

So the database was never the problem. 44 and 47 both did their job. The app
was calling the member tables directly, and PostgREST answered 401 — which
renders as an empty page rather than an error, which is why three rounds of
looking at views and grants found nothing.

WHERE THE CALLS CAME FROM
Not the budgets page — the TRANSACTIONS page. It branched its `transactions`
query for guests but left `budgets` and `transaction_lines` unbranched. Both
pages share that data, so the failure surfaced on budgets.

The dashboard had the same shape: `active_goals` sits ABOVE its
`if (isParent) return`, so a guest fired a 401 there on every single load.

I had checked the budgets page carefully and never looked at the other two.

FIXED
  Transactions.jsx   budgets → budgets_guest, transaction_lines →
                     ledger_lines_guest for guests
  Dashboard.jsx      the goals query moved inside a guard

A CHECK, SO THIS CANNOT RECUR SILENTLY
check-stale-copy.mjs now fails if a guest-reachable page queries a member-only
table without branching. It understands `if (isParent) return` as a guard, so
it does not flag correct code — it flagged one such line on the first run and I
taught it the difference rather than leaving a noisy check, because a check
people learn to ignore is worse than none.
